# __MOKKAPI_SERVICE_NAME__ — mokkapi mock (.NET 10)

Generated by [mokkapi](https://github.com/) from the service **`__MOKKAPI_SERVICE_ID__`**.
This is a self-contained .NET 10 Minimal API that reproduces the endpoints, response
variants, match rules, scenarios and Handlebars/faker templating you defined in mokkapi —
so you can run the mock on a **headless server** where the mokkapi desktop app can't be installed.

- **Listens on port `__MOKKAPI_PORT__`** by default (the port defined for this service).
- Active scenario: **`__MOKKAPI_SCENARIO__`** (override with the `MOKKAPI_SCENARIO` env var).
- Health check: `GET /__mokkapi/health`.

## Project layout

```
src/
  Program.cs            host setup, CORS, one explicit route per endpoint, /__mokkapi/health
  Endpoints.cs          your endpoints + variants (the data that changes per service)
  MockEngine.cs         per-request: normalise → select variant → render → respond
  Matcher.cs            variant selection + header/query/JSONPath match rules
  BodyRenderer.cs       Handlebars + faker (Bogus) body templating
  ServiceDefinition.cs  data model + JSON helpers
Dockerfile  docker-compose.yml  .dockerignore   publish-selfcontained.sh
```

## How to run — pick what your server has

### 1. Nothing installed → self-contained single binary (recommended for headless)

```bash
./publish-selfcontained.sh            # or: ./publish-selfcontained.sh linux-arm64
MOKKAPI_PORT=__MOKKAPI_PORT__ ./publish/MokkapiMock
```

Copy `./publish/MokkapiMock` to the server and run it — no .NET runtime required.

### 2. Docker available

```bash
docker compose up -d --build
# serves on host port __MOKKAPI_PORT__ (mapped to container 8080)
```

### 3. .NET 10 SDK/runtime installed

```bash
cd src && dotnet run          # development
# or, framework-dependent publish:
dotnet publish src/MokkapiMock.csproj -c Release -o publish
dotnet publish/MokkapiMock.dll
```

## Switching scenarios

```bash
MOKKAPI_SCENARIO="SomeScenario" ./publish/MokkapiMock
```

A variant answers when its scenario list is empty (active in all) **or** contains the
active scenario, and all of its match rules pass. `forcedVariantId` overrides everything.

## Faithfulness notes & known differences

- Matching, scenario selection, `forcedVariantId`, the first-variant fallback, the
  `501 no_match` response and Content-Type defaulting all mirror mokkapi exactly.
- Faker values come from **Bogus** (the .NET equivalent of faker.js): the *shape* matches
  (`{{faker.uuid}}`, `{{faker.email}}`, …) but exact random values will differ run to run.
- **HTTP only.** If the service used HTTPS in mokkapi, TLS is not reproduced here — point
  your client at `http://…:__MOKKAPI_PORT__`. Put it behind a reverse proxy if you need TLS.
- Request history is logged to **stdout** (not persisted to SQLite as in the desktop app).
- **Block helpers + adjacent braces:** simple expressions like `{{x}}` work even right
  before a `}` (e.g. `{"n":{{x}}}`). Inside a block helper, though, an expression placed
  immediately before a literal `}` (e.g. `{{#each items}}{"id":{{this.id}}}{{/each}}`) can
  trip Handlebars.Net's brace parser — add a space (`{{this.id}} }`) or use `{{json this}}`
  if you hit it.
